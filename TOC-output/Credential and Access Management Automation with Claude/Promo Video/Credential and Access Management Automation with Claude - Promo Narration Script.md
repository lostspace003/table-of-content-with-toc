# Credential and Access Management Automation with Claude - promo narration

Voice: the presenter's own cloned voice. Duration: 6.5 min.

**[hook]** A new network engineer joins on Monday. By Thursday they still cannot log in to a single load balancer, and five tickets are sitting in five different queues, each waiting for someone to remember the right role.

**[hook]** What if one agent read the joiner record, drafted every ticket, proposed every account with exactly the right privilege, and then waited for your approval before touching a device? That is credential and access management, done with Claude, done safely.

**[intro]** Gennoor Tech presents Credential and Access Management Automation with Claude.

**[story]** One joiner in. Every account and every ticket out. You build the workflow in ten increments across three days, and every increment is something you can run, review and demonstrate. Claude plans the access, drafts the tickets and explains each step. Deterministic Python code makes the A P I calls. A person approves anything that creates a credential. And everything is logged.

**[path0]** You start with the real workflow. Who the joiner is, which team they belong to, and what that team is entitled to on F5, NetScaler, Radware, Cisco A C I, ServiceNow, GitHub and Terraform, plus other load balancers, Anaya L B included. You turn that tribal knowledge into a role-to-entitlement matrix that is versioned, owned and reviewable.

**[path0]** Then you set up the tooling. Claude Code on your workstation, the Claude Agent S D K for the orchestrator, and M C P servers that expose ServiceNow and your identity source as read-only tools. You define structured J S O N outputs validated with Pydantic, so every access plan is an object with a schema, never free text. Feed it a malformed record, or a request for a role the matrix does not grant, and it rejects with a reason instead of guessing.

**[path1]** Day two begins with ticketing. Using the ServiceNow Table A P I you raise the request and one requested item per system, route each to the right fulfilment group, and let Flow Designer carry the manager approval. The agent writes the description and the justification. Your code owns the call, and it never raises the same ticket twice.

**[path2]** Then the devices. Local accounts on F5 through iControl REST and t m s h, with partition access and role. System users on NetScaler through the NITRO A P I, bound to a command policy for least privilege. Users on Radware Alteon and Cyber Controller. Local users and security domains on Cisco A P I C. And an adapter interface so other load balancers, Anaya L B among them, plug in without changing the orchestrator, or fall back to a ticket with exact manual instructions. Every account is a dry run first, with the exact request body on screen, then a gated apply, then a read-back and a test login.

**[path3]** Repository access is code. Team membership in GitHub is expressed in Terraform, opened as a pull request by Claude Code, planned by GitHub Actions and applied only after a reviewer merges. The joiner gets the right teams and the right repositories, and the Terraform state file is the record.

**[path3]** Day three is guardrails. Passwords are generated by code and delivered through a one-time channel the model never sees. Least privilege is enforced by the matrix, not by the prompt. Every approval, every A P I call, every response and every verification is written to an append-only audit log kept with the ticket. Then you verify the joiner end to end, send the hand-over, and run the same workflow in reverse for a leaver until every account and every team membership is gone.

**[labs]** Every lab runs against a sandbox: a ServiceNow developer instance, virtual F5 and NetScaler appliances, a lab Radware controller, the Cisco A C I simulator and a throwaway GitHub organisation. You will watch the agent refuse to grant an administrator role outside the matrix, trace one joiner through the audit log, and revoke access end to end.

**[mods]** Here is the full table of contents, 10 modules over three days. Day one: The new-joiner access workflow and the automation baseline; Setting up Claude Code, the Agent SDK and MCP for the access workflow; and Joiner intake and entitlement resolution. Day two: Raising tickets in the right channel with ServiceNow; Device accounts on F5 and Citrix NetScaler; Radware, Cisco ACI and other load balancers (Anaya LB); and Repository and infrastructure access as code with GitHub and Terraform. Day three: Guardrails, approvals and audit for credential workflows; Verification, hand-over and reversal for leavers and movers; and Capstone: one joiner, every system, fully audited.

**[princ]** Every build in this course follows six engineering principles. Model output is a proposal, never a fact. Authorization lives outside the model. A human approves every consequential action. Decisions and evidence are logged. The stack stays provider-agnostic. And quality is measured, not assumed.

**[stats]** Ten build steps. Three days, hands-on. Seven systems provisioned from one joiner record. And zero credentials created without approval.
