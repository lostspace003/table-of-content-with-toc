Course outline

Cisco ACI Upgrade Automation with Claude

Plan, validate and execute ACI fabric upgrades the Cisco way, with Claude drafting and code executing

3 days (8 hours per day) Intermediate to advanced Instructor-led, hands-on labs Capstone project

About this course

Who should attend

Enterprise network operations, data centre, NOC and network automation engineers who run Cisco ACI fabrics, in India and worldwide.

Prerequisites

  • Working knowledge of Cisco ACI: APIC, leaf and spine, tenants, vPC
  • Basic Python and REST API calls with JSON
  • Familiarity with change management and maintenance windows
  • Familiarity with an AI coding assistant is helpful, not required

What you will be able to do

  • Describe the Cisco-recommended ACI upgrade sequence: release selection, pre-upgrade validation, APIC cluster first, then switch groups, then post-checks
  • Build a Python client for the APIC REST API that discovers the fabric, runs the pre-upgrade validator and returns typed JSON
  • Use Claude Code, the Claude Agent SDK and an MCP server to plan upgrade groups and maintenance windows as schema-validated structured output
  • Create firmware and maintenance policies with deterministic Python and Ansible only after a human approves the plan in a GitHub pull request and a ServiceNow change
  • Produce pre and post upgrade evidence, a comparison report, a pause or rollback decision and a complete audit trail

Capstone project

Engineering principles used throughout

  • Model output is a proposal, not a fact: every finding and generated change is validated by deterministic checks and tests.
  • Authorization lives outside the model: tool access is enforced by application code, scoped credentials and policy.
  • Human approval for consequential actions: deploying a mitigation, changing production configuration, rotating credentials.
  • Decisions, evidence, model and tool versions, approvals and outcomes are logged without recording secrets.
  • A model adapter and a tool adapter layer keep every build provider-agnostic and enterprise-portable.
  • Quality is measured: false positives, false negatives, reliability, latency, cost and safe failure, not just a demo.
