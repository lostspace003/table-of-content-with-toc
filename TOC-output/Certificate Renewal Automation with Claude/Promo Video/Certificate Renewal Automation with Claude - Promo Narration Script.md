# Certificate Renewal Automation with Claude - promo narration

Voice: the presenter's own cloned voice. Duration: 6.5 min.

**[hook]** The certificate expired at midnight. Nobody knew it was bound to the payments virtual server. By the time the first alert fired, the queue was already full.

**[hook]** What if an agent had found it weeks earlier, planned the renewal across every load balancer you own, opened the change ticket, then waited for your approval before touching a single device? That is certificate renewal, done with Claude, done safely.

**[intro]** Gennoor Tech presents Certificate Renewal Automation with Claude.

**[story]** Every platform. One renewal pipeline. F5, NetScaler, Radware and other load balancers, handled by one plan, one approval and one audit trail. You build it in nine increments across three days, each one something you can run, review and demonstrate. Claude plans, drafts and explains. Deterministic Python executes. A person approves. Everything is logged.

**[path0]** You start with the certificate lifecycle as a load balancer actually sees it. Client S S L profiles and virtual servers on F5. Cert-key objects and bindings on NetScaler. Certificate repositories and S S L policies on Radware Alteon. You renew one certificate by hand, write down every step, and mark every point where a wrong chain, a mismatched key or a skipped H A sync would have caused an outage.

**[path0]** Then you set up your workbench. Claude Code with a project file that knows your naming rules and red lines. The Claude Agent S D K running Python tools with structured J S O N outputs. An M C P server that exposes read-only inventory calls and nothing else. After that, a discovery agent pulls every certificate, expiry date and binding from F5 iControl REST, the NetScaler NITRO A P I, the Radware Alteon REST A P I and an adapter for other load balancers, into one typed inventory.

**[path1]** On day two the planning agent arrives. It reads the inventory, groups certificates by expiry window, owner and blast radius, and drafts a renewal plan as structured J S O N. It must cite the inventory rows it used; a missing owner or an unverified binding blocks the plan rather than being guessed. Then it opens the change record through the ServiceNow Table A P I and hands it to a Flow Designer approval path. The C S R is generated by code, and the private key is never shown to the model.

**[path2]** Then the executors. Deterministic, tested Python that uploads, installs and binds the certificate on each platform. On F5 that is iControl REST and t m s h. On NetScaler, the NITRO A P I with primary-only writes and a saved config. On Radware, the Alteon REST A P I with apply and save as explicit steps. For other load balancers you build an adapter against the same contract. Claude writes the first draft and explains every call. Then pytest proves it against recorded device responses before it touches hardware. On day three the guardrails close in: an approved change, an open maintenance window, a device on the allow list, H A in sync. Miss any one and the install is refused with a logged reason.

**[path3]** Validation comes next. A T L S handshake test on every virtual server before and after. Chain, key match and serial checks. If the post-check fails, the executor rolls back to the previous certificate object automatically, and you will watch it do exactly that.

**[path3]** Finally you wire the whole thing into a GitHub pull request and a GitHub Actions run, so every renewal plan is reviewed like code, with tests, dry run and post-check report attached. Renewals are scheduled ahead of expiry and the certificate owner gets the report.

**[labs]** Every lab runs against lab devices, a lab certificate authority and recorded A P I responses, so you can break things safely. You will watch a renewal get blocked for a missing approval, break a chain on purpose, and roll back against the clock.

**[mods]** Here is the full table of contents, 9 modules over three days. Day one: Certificate lifecycle on load balancers and the automation baseline; Setting up Claude Code, the Agent SDK and MCP for certificate work; and Certificate inventory and expiry discovery across platforms. Day two: Renewal planning agent and ServiceNow change records; Deterministic executor: F5 BIG-IP with iControl REST and tmsh; and Deterministic executors: NetScaler NITRO, Radware Alteon and other load balancers (Anaya LB). Day three: Guardrails, approvals and audit for certificate changes; Pre- and post-checks, rollback and the GitHub pipeline; and Capstone: end-to-end certificate renewal across the lab estate.

**[princ]** Every build in this course follows six engineering principles. Model output is a proposal, never a fact. Authorization lives outside the model. A human approves every consequential action. Decisions and evidence are logged. The stack stays provider-agnostic. And quality is measured, not assumed.
